# Kubernetes Adapter and Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `deploy.target: kubernetes` brings the Satat platform up on k3d through a second `deploy.Target`, and the worker runs agents as one-shot `SandboxClaim`s through a launcher that passes `launcher/conformance` unchanged.

**Architecture:** `launcher/kubernetes` renders each lane's objects (namespace, `SandboxTemplate`, `SandboxWarmPool`, managed network policy, worker `Role`) and drives claims with client-go. A static `satat-entry` wrapper, copied in by an init container from the platform image, waits out the network-policy gap, loads mounted secrets, runs the lane command and writes one framed result block to the pod log. `deploy/kubernetes` renders values plus lane objects, builds and pushes the platform image, and drives `kubectl` and `helm` against an embedded chart in `deploy/helm/satat/`.

**Tech Stack:** Go 1.27, `k8s.io/client-go` / `k8s.io/api` / `k8s.io/apimachinery` v0.37.1 (dynamic + typed clients, fakes for tests), agent-sandbox v1.0.7 (`extensions.agents.x-k8s.io/v1beta1`), Helm 3/4 CLI, kubectl, k3d v5.9.0, k3s `v1.34.12-k3s1`.

**Spec:** [docs/research/v2/k8s-adapter.md](../../research/v2/k8s-adapter.md). API facts: `docs/scratch/agent-sandbox-api.md` (gitignored; the essentials are copied into Global Constraints).

## Review Focus

1. **Probe target down vs policy not yet enforced:** a refused probe could mean Postgres is down rather than the policy being applied. The wrapper accepts refusal or dial timeout as "blocked" and keeps waiting while connections succeed. Test in Task 2 (succeeds-then-refuses → proceeds; always succeeds → exit 125 within the timeout).
2. **A step re-run right after the previous run's cleanup:** the old claim is still terminating, so `Create` returns `AlreadyExists` for a dying claim. The launcher waits for the old claim's deletion (it has a `deletionTimestamp`) and then creates, rather than adopting a dead claim. Test in Task 4.
3. **A secret value that the step prints, and one split across the 1 MiB stream cap:** the wrapper scrubs before it caps. Test in Task 2.
4. **`deploy up` against a context that is not the k3d one, or with no agent-sandbox CRDs:** it stops before any change, naming the context. Test in Task 6.
5. **A lane whose pass_env secret is missing in `deploy.secrets` resolution at up time, or a lane removed from `satat.yaml`:** up fails before helm on the first; on the second, the namespace stays (not pruned) and `up` prints a notice naming it. Test in Task 6.

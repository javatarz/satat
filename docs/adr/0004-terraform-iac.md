# Terraform for infrastructure-as-code

The VM, security group, Elastic IP, and all supporting infrastructure are defined as Terraform resources in this repo and applied through GitHub Actions (plan on pull request, apply on merge to main), never from a local machine. This keeps every change reviewable via pull request and the infrastructure reproducible. State lives in S3 with the native lockfile (Terraform ≥ 1.10), and runs authenticate to AWS via GitHub OIDC — no long-lived cloud credentials are stored. A one-time local bootstrap creates the state bucket, the OIDC provider, and the Terraform IAM role. Alternatives: Ansible (mutation-oriented rather than declarative, harder to reason about drift) or manual provisioning (unreviewable, unreproducible).
